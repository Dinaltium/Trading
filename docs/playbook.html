01The one-sentence version

You built a robot that watches SPY and QQQ options every 15 minutes, one AI model proposes a cautious defined-risk trade, and a separate rulebook written in plain Python — not AI, no persuading it — is the only thing allowed to let real (paper) money move.

Everything else in this document is detail on top of that one sentence.

02Two separate systems — this is the part that's been confusing

There is no single "the project is running" switch. There are two independent things, in two different places, that only talk to each other through GitHub. Neither one can see or control the other directly.

Local machine — the trader

  • Runs on your computer, inside a terminal you start yourself.
  • This is the part that actually makes decisions and places trades.
  • Talks to Alpaca, Groq, Featherless, Mistral, and your Claude Code CLI.
  • Writes one log entry every cycle, pushes it to GitHub.
  • Stops the instant you close the terminal or your PC sleeps. Nothing restarts it for you.
  • Started with one command: python -m src.scheduler

Vercel — the window

  • Runs on Vercel's servers, always on, needs nothing from you day to day.
  • This is only a website — it cannot place, cancel, or affect any trade.
  • Reads the log file your local machine pushed to GitHub, shows it as charts and tables.
  • Redeploys itself automatically whenever you git push.
  • If the local trader isn't running, this page just shows old data — it has no idea the trader stopped.
  • Public dashboard: no login needed. /admin: password-gated, changes settings only.

So: "is it running?" only has one real answer — is the local terminal with src.scheduler open right now? The website being live tells you nothing about that.

03What happens every 15 minutes, in order

1
Scheduler wakes upChecks the market clock via Alpaca. If closed, or trading is paused via /admin, it stops here and waits for the next tick.
2
Pull live dataCurrent SPY/QQQ price, the full live option chain (strikes, IV, Greeks), and daily bars for the last ~2.4 years.
3
Compute the signalsIV Rank + VRP (is volatility expensive right now?) from the option chain. A calibrated P(Up) probability from a LightGBM model trained on the price history.
4
Ask 4 AI models the same question Same signals, same instructions, sent to all four in parallel.
LIVEGroq — its answer is the one that can actually execute.
SHADOWClaude Code CLI, Featherless, Mistral — logged for comparison, never touch the account.
5
Risk gate reviews the live decisionPure Python, zero AI. Checks Kelly-criterion position size, max loss per trade, total open risk, daily drawdown, diversification. Approves with an exact contract count, or rejects with a reason.
6
Execute, if approvedEvery leg of the spread submits as one atomic order — all fill together or none do. No partial, unbalanced positions possible.
7
Log and pushSignals, all 4 decisions, the risk verdict, and the fill result get written to one record, pushed to GitHub. The dashboard picks it up on its next page load.

04Every file, what it does

Signals — turning raw market data into numbers worth reasoning about
src/signals/iv_rank.py

Computes current implied volatility, compares it to realized volatility (VRP) and to a running log of past IV readings (IV Rank). Answers: is volatility expensive or cheap right now?

src/signals/direction.py

Trains a LightGBM model on ~2.4 years of daily bars, outputs one calibrated number: probability price is up in 3 days. The only quantitative number the AI reasons with.

Decision & risk — the AI proposes, the code disposes
src/decision_schema.py

The exact instructions every AI model receives — signals in, one of 4 strategies out, in strict JSON. Same prompt to all 4 models so the comparison is fair.

src/model_adapter.py

One function that talks to Groq, Featherless, and Mistral (same API shape), plus a separate subprocess wrapper for Claude Code CLI. Every failure is caught and logged, never crashes the loop.

src/risk_gate.py

The rulebook. No AI. Takes a proposed trade + account state, checks it against config/risk_limits.yaml, sizes it with Kelly criterion, approves or rejects. This is what makes "risk gates" a real, checkable claim instead of a slide.

config/risk_limits.yaml

The actual numbers: max 2% loss per trade, 10% total open risk, 5% daily drawdown halt. Hand-edited only — never remotely adjustable, on purpose.

Execution & orchestration — tying it into one loop
src/execution.py

Picks real option contracts off the live chain by delta (never a guessed strike), builds bull-call / bear-put / iron-condor spreads, submits every leg as one atomic order.

src/orchestrator.py

The conductor. Runs signals → 4 decisions → risk gate → execution → log, for one underlying, one cycle. Everything above is a tool this file calls in order.

src/scheduler.py

Runs the orchestrator every 15 minutes, only in market hours, with a 90-second timeout per cycle so one stuck network call can't freeze the whole process.

src/audit_log.py

Writes one JSON record per cycle to logs/audit_log.jsonl, pushes that file to GitHub once per scheduler tick so the dashboard can see it.

src/live_settings.py

Reads config/live_settings.json from GitHub each tick: which model is live, which tickers are active, whether trading is paused. This is what /admin controls.

Dashboard — the public window (dashboard/)
dashboard/src/app/page.tsx

The public, no-login page. Equity chart, live-vs-shadow comparison, full cycle table. Reads the GitHub-hosted log fresh on every visit.

dashboard/src/lib/audit.ts

Fetches and parses the audit log from GitHub's raw file URL. The only place the dashboard's data actually comes from.

dashboard/src/app/admin/page.tsx

Password-gated settings form: which model trades live, which tickers, pause/resume. Writes to GitHub via an API route — never touches risk limits.

dashboard/src/proxy.ts

Checks a password before letting anyone reach /admin or its API route. The public page is untouched by this file and stays open.

05Why it's built this way

Why Groq is the only one that trades, and 3 others just watch

Running all 4 models every cycle — one live, three shadow — gives a continuous, honest comparison of a paid model (Claude) against free open models, without ever risking the account on an untested one. That comparison is itself part of the "Creativity" story for judges.

Why the risk gate is plain Python, not AI

An LLM can be talked into anything with a convincing-sounding argument. A hard-coded rule can't be. Judges can read risk_gate.py directly and verify the limits are real, not claimed.

Why every spread submits as one atomic order

Submitting legs one at a time risks a partial fill — you buy the protective leg but the sell leg fails, and you're holding an undefined-risk position by accident. One atomic order fills completely or not at all.

Why only SPY and QQQ

Index ETFs don't report individual earnings — no earnings-crush risk, no earnings-calendar data source needed. That's two entire problems that disappear for free by picking the right underlyings.

Why the dashboard reads from GitHub instead of your machine directly

Vercel's servers have no access to your laptop's filesystem. Pushing the log to GitHub after each cycle is the only way a public website can show "live" data from a trader running on a private computer.

Why /admin can't touch risk limits

Even password-protected, a remotely-adjustable risk limit undermines the entire "the risk gate can't be talked into anything" story. Those numbers only change by hand-editing a file and pushing it.

One manual test cycle — no real order placed
cd C:\Projects\Trading
.venv\Scripts\activate
python -c "from dotenv import load_dotenv; load_dotenv(override=True); from src.orchestrator import run_cycle; print(run_cycle('SPY', dry_run=True))"

Fetches real live data, gets real AI decisions, evaluates the risk gate — but dry_run=True means nothing actually submits to Alpaca.

The real thing — starts the autonomous 15-minute loop
cd C:\Projects\Trading
.venv\Scripts\activate
python -m src.scheduler

Leave this terminal open. It checks market hours, runs every 15 minutes, submits real (paper) orders when the risk gate approves, and pushes results to the dashboard on its own. Closing the terminal stops everything.

08If a judge asks — quick answers

What makes this autonomous, not just an AI wrapper?

The scheduler runs every 15 minutes with zero human input — reads live data, gets an AI decision, risk-checks it, executes if approved. Nobody clicks anything mid-cycle.

How do you know the risk limits are real, not just claimed?

They're in a plain Python file, risk_gate.py, with no AI involved anywhere in it — you can read the exact rules and watch it reject a trade live in the audit log.

Why 4 AI models?

Only Groq trades. The other 3 run the same decision every cycle purely for comparison — a real benchmark of a paid model against free open ones, using identical signals and instructions.

What stops a bad AI decision from blowing up the account?

The risk gate sits between every AI decision and Alpaca. It sizes positions with the Kelly criterion off a calibrated ML probability — never the AI's own self-reported confidence — and can reject outright.

Is the dashboard live data or a screenshot?

Live. It fetches the audit log fresh from GitHub on every page load — no caching, no static snapshot.

09Glossary

IV Rank
Where today's implied volatility sits versus its own recent history — high means options are "expensive" right now.
VRP
Volatility Risk Premium — implied volatility minus realized volatility. Positive means the market is pricing in more movement than has actually happened.
P(Up)
The LightGBM model's calibrated probability that price is higher in 3 days. A real number, not a vibe.
Kelly criterion
A formula for how much to bet given your edge and payoff — used here at quarter-strength to size positions conservatively.
Iron condor
A 4-leg options trade that profits if price stays in a range — used when volatility is high and direction is unclear.
Bull call / bear put spread
2-leg directional trades with a capped maximum loss, used when the model leans clearly up or down.
Shadow model
An AI whose decision gets logged every cycle but never executes — pure comparison data.
Atomic order
All legs of a multi-leg trade submit as one order — they fill together or not at all.
